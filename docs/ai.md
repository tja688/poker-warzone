# AI 与模拟设计

三种策略全部先调用 `legalActions`，只会选择规则引擎承认的操作。UI 建议与代打也调用同一套决策代码。

## 信息边界

AI 可见双方 5 场地、战区、控制区是否使用、胜场、弃牌次数、当前小局和回合编号。剩余牌集合用完整 52 张减去桌面牌推算。决策函数不读取实际牌库内容与排列、洗牌 RNG 状态或游戏种子。测试会更改隐藏牌库、种子和 RNG，检查三种策略的决策保持相同。

## 随机

对全部合法操作列表做公开状态哈希选择。每个具体组合是一个候选，并非先按三类操作均匀分配概率。这提供稳定、可复现的弱策略基线；不会为了等待好牌主动跳过。

## 贪心

最大化行动后的德州牌型和逐级踢脚；同牌型倾向吸满。小局第一次吸牌时优先用可用控制区，每区至多一张。没有更高价值的吸牌或换牌时弃掉普通牌，偏向多重抽。平分候选按固定来源顺序选择。

这是对策划案第 11.4 节基准思路的具体实现，并不是最优策略证明。每个目标牌型的最少换牌数由引擎穷举求出，AI 不自行放宽限制。

## 策略

使用可解释的启发式评分，没有读取隐藏牌序进行搜索：

- 已成牌型与踢脚形成基础分；未满五张时降低即时牌型权重。
- 从公开推算的剩余集合评估补成重复点数的机会，并奖励同花、顺子的潜在路线。
- 满五张时额外重视牌型；对手也满五张且能够超过其明牌时加分。
- 前期取用控制区有资源消耗成本，后期减小成本。
- 换牌严格升级时加分；弃牌保留与当前牌相配的点数及未完成路线，倾向丢弃无关联的牌。

这是一套供测试的资源规划 AI，并未精确计算所有未来补牌或求解整场最优策略。当前 1,000 场对照中策略方胜率 48.1%，不足以证明优于贪心；界面使用风格名称，不承诺难度排序。

## 确定性与回合时序

引擎以 FNV-1a 字符串种子初始化 Mulberry32 PRNG，以 Fisher–Yates 洗牌。只有新对局的 UI 随机种子生成使用浏览器随机值；规则推进、AI 与模拟不使用 `Math.random`。

返回牌放在数组底部；回合推进严格先补当前玩家空普通场地，再洗整个牌库，再检查操作。卡住回合也执行这一时序。新小局先由先手方补普通区，再补另一方，洗牌后确定新战区，最后进入首回合。

## 统计口径

- 每场模拟的对局种子是 `批次种子:从0开始的序号`。单场首轮先手随机，后续败者先手，平局随机。
- A/B 大局胜率、首轮先手整场胜率及五局占比：分母是已完成大局数，大局平局另列。
- 小局平局率：平局小局 / 所有已结算小局。
- 续胜率：只取上一局有唯一胜者、且存在下一局的转移；下一局仍由该方独胜才计续胜，下一局平局单列。网页给出 95% Wilson 区间。
- 牌型：每小局双方各计一手，分母为小局数 × 2。
- 每次实际状态推进检查牌数守恒、场地容量、牌库余量、控制区保留和行动上限；具体换牌、底部返回、补牌时序及结算语义另有单元测试。
- Web Worker 只回传聚合统计；停止后保留最后一批已完成大局，未完成大局不会混入统计。导航离开实验室会终止当前批次。

命令行参数和网页均复用 `simulateOne`；网页批次上限 200,000，CLI 支持任意合理正整数场数。大样本消耗时间与设备和策略有关。
